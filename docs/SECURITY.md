# Security boundaries

Roster wallets are declarations, not identity proofs. Only each actual named sender may submit its own statement. A moderator cannot overwrite preferences or freeze an incomplete roster. Submitted statements, roster and topics are immutable. Exact revisions reject stale writes; owner-qualified IDs prevent cross-wallet overwrite.

All member text is untrusted source material. Native validators independently derive the entire strict-ranking profile from the same original signed statements. Quotes must belong to the corresponding signer. The accepted anchor is the complete original signed statement; each validator independently derives the whole ranking from that source, rather than accepting schema, a plausible group agenda or a confidence score. Shared model errors remain possible. Missing comparisons and ties remain UNKNOWN; exceptions are technical failures and cannot turn into valid uncertain ballots.

The exact solver lists all at-most-120 permutations, computes integer pairwise-disagreement costs and exposes all optima. The model cannot choose a convenient order or hide a cyclic profile. A source-bound hash plus certificate recomputation gates start. During execution, the moderator can acknowledge only the next canonical topic; completed is always a prefix, and the final step is terminal. Pre-start cancellation is available to any member. The protocol does not guarantee the moderator will advance a running meeting.

The topic-index tie-break is explicit and manipulable by choosing the original topic order before creation; it is not described as unbiased randomness. Roster selection can exclude people or include related wallets. This small-group protocol is neither a public election system nor strategy-proof social choice. No state says that an acknowledged discussion actually occurred.

No payable methods, token transfers, private frontend model service or custody exist. Statements and signer addresses are public. Independent local inversion-count verification and complete three-topic profile tests validate the deterministic certificate; only actual recorded network transactions establish native consensus execution.
